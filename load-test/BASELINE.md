# 부하 측정 기준선

이후 성능을 바꾸는 작업의 "고치기 전" 수치임. 합격 여부는 판정하지 않았음. 시나리오의 부하량·요청 구성은 설계에서 정한 [가정] 값임

| 항목 | 값 |
|---|---|
| PC | Intel i7-13650HX(14코어 20스레드), 메모리 64GB, Windows 11 Home |
| 구성 | 앱·DB·Redis·k6가 모두 같은 PC. 서버 1대 |

| DB·Redis | Docker Desktop(엔진 28.1.1) 컨테이너. MySQL 8.0.46, Redis 7 |
| k6 | `grafana/k6:0.54.0` 컨테이너에서 `host.docker.internal:8080`으로 호출. Docker Desktop의 호스트 연결을 거치므로 지연이 그만큼 섞임 |
| 데이터 | `seed.sql`. 회원 1,003명, 계좌 1,002개, 종목 20개, 보유 내역 5,000건, 거래 기록 10,002건. 측정마다 다시 넣음 |

- 불일치는 측정 직후 `check.sql`의 7개 검사(잔액 = 거래 기록 합계, 음수 잔액·수량, 묶인 금액·수량 = 미체결 주문 합계, 체결 수 = 매매 대금 기록 수, 보유 수량 = 초기 + 체결 매수 - 체결 매도)의 합임. 검사마다 일부러 값을 틀어 1이 나오는지 확인했음

- 같은 계좌 집중의 오류율에는 업무 거절(400)을 넣지 않았음. 결과: 출금 성공 100건·잔액 부족 200건(잔액 100만 원 → 0원), 주문 성공 99건·잔액 부족 201건(최대 99건), 취소 성공 98건·"미체결 주문 아님" 202건. 중복 취소·초과 출금·음수 잔액 0건

## 다시 재는 방법

```bash
docker compose up -d                                   # MySQL·Redis·Prometheus·Grafana
JWT_SECRET=$(openssl rand -base64 48) JWT_ACCESS_TOKEN_SECONDS=7200 ./gradlew bootRun   # 30분 측정 중 토큰이 만료되지 않게 2시간
cd load-test
docker exec -i <mysql 컨테이너> mysql -uaccount -paccount --default-character-set=utf8mb4 accountSystem < seed.sql
docker run --rm -v "$PWD:/scripts" grafana/k6:0.54.0 run --summary-export /scripts/results/<날짜>-normal-summary.json /scripts/normal.js
docker exec -i <mysql 컨테이너> mysql -uaccount -paccount --default-character-set=utf8mb4 -t accountSystem < check.sql
# 같은 계좌 집중은 seed.sql을 다시 넣고 hot-account.js로 같은 순서
```

- 측정 구간 그래프는 Grafana `StockAccount 기본` 대시보드에서 위 시각(평시 10:23:53~10:53:58, 집중 10:54:26~10:55:49, 한국 시각)으로 봄
